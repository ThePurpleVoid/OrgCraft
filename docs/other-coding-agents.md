# Other coding agents: `AGENTS.md`

Many coding agents read a root `AGENTS.md` as their project instructions. Turn on the `agents-md` target and sync writes one from the same sources as the Claude Code project instructions, so a session in another agent can find its role, follow the protocols and report to the board.

```json
{ "targets": ["claude-code", "agents-md"] }
```

A team without `targets` gets `["claude-code"]` and sync writes exactly what it wrote before. `validate` and `sync` refuse a target the kit does not have.

## What `AGENTS.md` holds

- **Who you are.** The role comes from `AGENT_TEAM_ROLE` in `.agent-team/local.env`, or from the first message ("You are web-dev. Read docs/team/roles/web-dev.md").
- **Before anything else, in every task.** Report `status working`, read the role brief and `docs/team/protocols.md`, read the role's memory file: `memory/<role>.md` in the board folder (`AGENT_TEAM_HOME`) when the tool keeps no project memory, or `.agent-team/memory/<role>.md` in the checkout when there is no board folder. Sync adds `.agent-team/memory/` to `.gitignore`.
- **Reporting to the board** with `node scripts/agent-team/report.mjs`, which needs Node only (no bash, no `jq`): `status working`, `heartbeat`, `status waiting`, `handoff`, `bug`, `signoff`, `blocked`, `status done`.
- **The project instructions**: the company, how work moves, the standing rules, the model tiers by tier name (deep, standard, routine, light) for each agent to map however it can.

It names no vendor and no model. A test checks this against a list of vendor and model names.

## A hand-written `AGENTS.md` is kept

Sync writes the kit's text between two markers and leaves everything else in the file alone:

```md
# Our agents
Use pnpm, never npm.

<!-- agent-team:start: generated by Agent Team Kit 0.15.0. Do not edit between these markers: ... -->
...
<!-- agent-team:end -->
```

`sync.sh check` fails when the text between the markers is stale or edited, never because of your own lines. Turn the target off and sync removes only the kit's block; a file that held nothing else is deleted.

## What works with Claude Code and with other agents

Hooks are a Claude Code feature, so other agents miss what hooks do. The governance that matters most still holds, because the merge gate and CI check it, and the runner checks it in hosted runs.

| | Claude Code | Other agents (`AGENTS.md`) |
| --- | --- | --- |
| Role brief, protocols, project instructions | Yes | Yes |
| Role memory between sessions | Project memory | A file in the board folder, or in the checkout (never committed) |
| Board reports the role makes (status, HANDOFF, BUG, SIGNOFF, BLOCKED) | Yes | Yes, with the Node reporter |
| Automatic liveness (start, heartbeat, idle and stop from hooks) | Yes | No: the board shows only the role's own reports, and its card says **Self-reported** |
| Ownership guard before each edit | Yes, live | No: one writer per area is still checked by the merge gate and CI, and by the runner in hosted runs |
| Subagent and teammate reports | Yes | No |
| Built-in agent teams export (`"agentTeams": true`) | Yes | No |
| Merge gate, CI checks, approvals | Yes | Yes |
| A repository with both `CLAUDE.md` and `AGENTS.md` | Claude Code reads its own files | Each agent reads its own instruction file. opencode 1.19.5 reads `CLAUDE.md` only when there is no `AGENTS.md`, so the rules are not loaded twice. The flip side: once the kit writes `AGENTS.md`, opencode stops reading your `CLAUDE.md`, so move shared project notes into `AGENTS.md`, outside the kit's markers |

The board marks a thread that has reports and no hook events as **Self-reported**, on its card and in its panel, so the owner can see why a card may go quiet.

## Proof with two agents (kit 0.15.0)

The story's walk asks two coding agents other than Claude Code, told only "You are web-dev; start the task 'Add a footer'", to read their brief and report `status working`. Until the owner sets a model key there are no model calls, so the proof has two offline halves. The live walk is **pending owner key**.

**1. Each agent loads the root `AGENTS.md`.** Read from the installed packages' own file lookup, without running a model and without any credential. The two agents were installed from npm on 2026-11-06:

| Agent | Version | How it finds `AGENTS.md` (from the installed binary) |
| --- | --- | --- |
| Codex CLI (`@openai/codex`) | 0.167.0 | `core/src/agents_md.rs`: project documents in the order `AGENTS.override.md`, `AGENTS.md`, then `project_doc_fallback_filenames`; read up to `project_doc_max_bytes = 32768`. The kit's `AGENTS.md` for the engineering preset is about 8.7 KB. |
| opencode (`opencode-ai`) | 1.19.5 | The instruction file names are `["AGENTS.md", "CLAUDE.md", "CONTEXT.md"]` (`CLAUDE.md` unless `disableClaudeCodePrompt`), found by `findUp` from the working directory to the worktree root, unless `OPENCODE_DISABLE_PROJECT_CONFIG` is set. It stops at the first name it finds, so in a repository with both `AGENTS.md` and `CLAUDE.md` it loads `AGENTS.md` only: the team's rules are never loaded twice. |

A third agent, Gemini CLI (`@google/gemini-cli` 0.67.0), reads `GEMINI.md` by default and reads `AGENTS.md` only when its `context.fileName` setting names it, so it is not one of the two.

**2. The reporter commands in `AGENTS.md` work as written.** `tests/agents-md.test.mjs` takes every `node scripts/agent-team/report.mjs` line from a generated `AGENTS.md`, fills in `web-dev` and "Add a footer", runs each with `PATH=/nonexistent` (so no bash, no `jq`) and checks the board's event log has web-dev `working` on "Add a footer". The board shows that thread as **Self-reported**, because no hook event came from it (`tests/dashboard.test.mjs`).
