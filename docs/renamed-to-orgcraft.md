# Agent Team Kit is now OrgCraft

On 2026-11-09 the product was renamed from **Agent Team Kit** to **OrgCraft**, and the Studio from **Agent Team Studio** to **OrgCraft Studio**. It's the same code, the same release tags, and the same team files. This page lists what changed for a team that already uses the kit, and what didn't.

## What changed

- **The package name** is `orgcraft` (was `agent-team-kit`). The command is now `orgcraft`, and `agent-team` keeps working as an alias.
- **Import paths in the docs** read `orgcraft/studio/handler`, `orgcraft/studio/github-app-token`, `orgcraft/team-model` and `orgcraft/github-app`. If your app depends on the kit under the old name, for example `"agent-team-kit": "github:…"` in `package.json`, your imports keep working, because npm installs a dependency under the name you gave it. To switch, rename the dependency key to `orgcraft` and update the imports in the same change.
- **Words on screen and in generated files.** The Studio's title and sign-in pages, the sign-in email subject ("Your code for OrgCraft Studio: …"), and the marker at the top of generated files ("Generated by OrgCraft X.Y.Z") all use the new name.
- **The publish trailer** on Studio commits now ends `via OrgCraft Studio` (was `via Agent Team Studio`).
- **The pull request footer** reads "Published from OrgCraft Studio".

## What didn't change, and why

- **`.agent-team/`, `docs/team/` and `scripts/agent-team/`** keep their paths. Every team's repository, CI and scripts point at them, and moving them would break every team at once for no gain.
- **`AGENT_TEAM_*` settings** (`AGENT_TEAM_KIT_DIR`, `AGENT_TEAM_PROJECT`, `AGENT_TEAM_GITHUB_APP_ID` and the rest) keep their names. They live in other people's secret stores and deployment settings.
- **Schema and event ids** such as `agent-team/team-spec@1` and `agent-team/role-pack@1` keep their names. They are data ids, not branding, and changing them would make every existing team file invalid.
- **The `<!-- agent-team:start … -->` / `<!-- agent-team:end -->` markers** in AGENTS.md keep their names, so a sync finds the block an older version wrote.
- **Release tags** are the same commits as before the rename.

## What a team sees on its next sync

Only text. When a team moves its pin to the first release with the new name, the generated files' header line reads "Generated by OrgCraft" and the kit's name in the generated README and protocols changes. Nothing about how roles, gates or the board behave changes.

Readers accept both spellings: the kit recognises files generated before the rename (the "Generated by Agent Team Kit" marker, and the old `export-subagents` marker), so an older checkout and a newer one can sit side by side during the upgrade.

## Later

A guided move of `.agent-team/` and `AGENT_TEAM_*` to new names may come in a later major version. If it does, it will read both names for at least two minor versions and come with a one-command migration. Nothing is planned for 0.x.
